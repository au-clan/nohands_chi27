# Prolific screening (prescreen filters, reward, study description)

The study description below is the text participants saw on Prolific. Sections after it record the
audience filters, reward, and recruitment logistics.

## Study description (as shown on Prolific)

This study involves active, hands-on work. The main task is a 10-minute live coding session in a
virtual desktop, not a survey. Please read the requirements before accepting.

You will be assigned a voice-controlled programming tool and asked to complete small coding
exercises using only your voice — no typing code, no navigating files with the mouse.

**Requirements — return the study immediately if you do not meet all of these:**

- A desktop or laptop computer. Phones and tablets will not work.
- A working microphone, and willingness to grant your browser microphone access. The tool cannot
  function without this.
- A quiet enough environment to speak aloud continuously for 10 minutes.
- Some programming experience — you should be comfortable reading and editing code. Expert-level
  skill is not needed.
- A stable internet connection. The virtual desktop is streamed to your browser, so a dropped
  connection will end your session.

**What you will do:**

1. Pre-experiment survey (~5 min) — programming background and tool familiarity.
2. 10-minute hands-free coding session in a browser-based virtual desktop. The voice tool is
   already installed and set up. Complete as many exercises as you can, using voice only.
3. Post-experiment survey (~5 min). Your completion code is given at the end of this survey.

**Total time: approximately 20–30 minutes.**

**Important — please read before accepting:**

Voice programming tools are genuinely difficult to use and will often misunderstand you. That
difficulty is exactly what we are studying, so a session where the tool fights you is still a
valuable result. We ask that you stay engaged and keep making real attempts for the full 10
minutes. Submissions showing little or no genuine attempt will be rejected.

If the tool is not working at all — no response to your voice whatsoever — please message the
researchers rather than sitting idle.

**Data collected:** your session in the virtual desktop is screen- and audio-recorded, and
keystroke and mouse events are logged. Recording is limited to the virtual desktop in your browser
tab; nothing else on the participant's computer is visible. No webcam. All data is pseudonymised.
Full details are in the consent form at the start of the first survey (`consent.md`).

**Payment:** submissions are reviewed and approved within 24 to 72 hours, once data quality has
been checked.

## Mandatory steps inside the desktop (missing from the Prolific description)

The Prolific description does **not** mention two requirements that are enforced inside the virtual
desktop (see `start_dialog.txt` for the exact dialog text):

- **Enabling the microphone is mandatory** — without it the participant cannot be paid.
- **Watching the 2-minute tutorial video is mandatory** — skipping it may get the submission
  rejected. Nothing is timed while the video plays, so it is not part of the 10-minute session.

## Audience selection (prescreen filters)

- Device: desktop **and** microphone
- Microphone available
- Any computer programming experience
- Language / dialect: regional dialects of standard British English or standard American English

## Reward

£15–20 **per hour** (the study takes roughly 20–30 minutes, so the actual payment per participant
is a proportional share of that).

## Recruitment logistics

- **Concurrency limit:** participant access was limited to **3 at a time**, because the study
  infrastructure can reliably spin up 3 virtual desktops simultaneously.
- **Linking data across systems:** the Prolific participant ID, study ID, and session ID were
  passed from Prolific into the pre-study survey, and carried through to the virtual desktop and the
  post-study survey. This is how the pre-study survey, the recorded session, and the post-study
  survey were matched to the same participant, and how sessions were tied to genuine Prolific
  participants so that access could not be abused (for example, shared or reused links). The
  specific URLs and keys are intentionally not recorded here.
